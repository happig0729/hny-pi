# 设计 01：产品工作台

## 布局原则

桌面端采用三栏布局：

- 左侧：模块导航、目录树或生命周期导航。
- 中间：结构化业务主工作区。
- 右侧：当前 Agent 工作层。

移动端采用栈式布局，AI 工作层折叠为底部或抽屉，但业务主操作仍优先展示。

## 工作台列表

### 全局工作台

展示租户级或用户级概览：

- 项目总数。
- 待审核数量。
- 待签章数量。
- 预检失败项目。
- 存储和配额风险。
- AI 生成的运营摘要。

### 项目驾驶舱

展示单项目全生命周期：

- 当前 LifecycleStage。
- 档案项完成率。
- 缺项、未签章、审核退回、映射缺失。
- 下一步 Action Proposal。
- 项目成员和待办责任人。

### 文件中台

展示文件进入系统后的生产状态：

- 目录树。
- 文件列表。
- 解析状态。
- AI 分类和置信度。
- 著录字段建议。
- 批量确认栏。

### 编制工作台

展示模板表单和字段来源：

- 表单预览。
- 字段编辑。
- 字段来源：项目默认、历史记录、AI 推断、人工输入。
- 缺失字段。
- 提交审核或签章入口。

### 审核工作台

展示质量控制：

- 文件预览。
- AI 风险标注。
- 审核意见草稿。
- 通过、退回、整改任务。
- 审核历史。

### 签章工作台

展示签章流转：

- SigningTask。
- SigningNode。
- 节点状态。
- 印章有效性。
- 待签聚合。
- 拒签处理。

### 归档工作台

展示交付闭环：

- 预检通过率。
- 阻断项和警告项。
- 归档包草案。
- 采集记录。
- 项目/单体锁定状态。

### 权限审计工作台

展示治理：

- OperationLog。
- AgentRunRecord。
- Action Type。
- operationId。
- EvidenceRef。
- 用户确认记录。

## 右侧 Agent 面板

固定结构：

- Agent 名称和职责。
- 当前上下文判断。
- 建议动作。
- Ontology Scope。
- 证据。
- Action Proposal。
- 输入框。

## 可独立验证的 UI 规则

- 每个页面都有明确 Agent，但用户不需要手动选择 8 个聊天机器人。
- 所有写操作按钮都能展开 Action Proposal。
- 所有 AI 判断都能展开证据。
- 高风险动作必须显示二次确认。
- 批处理操作必须显示影响对象数量和低置信度项。
